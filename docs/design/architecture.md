# System Architecture

This page explains the major components of the system and how they interact.

![Architecture Diagram](images/architecture-diagram.png)

---

# Overview

The Campus Lost and Found Platform follows a simple three-tier architecture.

1. Frontend
2. Backend
3. Database

---

# User Browser

Users access the platform using a web browser.

Examples:

- Chrome
- Edge
- Safari
- Firefox

---

# Frontend

Technologies:

- HTML
- CSS
- JavaScript

Responsibilities:

- Display pages
- Handle user interactions
- Validate form inputs
- Communicate with backend services

---

# Backend

Planned Technology:

- Flask (Python)

Responsibilities:

- Process requests
- Store and retrieve item records
- Handle claim requests
- Manage user reports

---

# Database

Planned Technology:

- MySQL

Responsibilities:

- Store lost-item records
- Store found-item records
- Store claim requests
- Store user report information

---

# Future Expansion

Future versions may include:

- User authentication
- Image uploads
- Email notifications
- Administrative dashboards

---

# Conclusion

This architecture provides a scalable foundation for the Campus Lost and Found Platform while remaining simple enough for the project scope.
