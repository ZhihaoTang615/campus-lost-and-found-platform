# Known Limitations

These are confirmed boundaries of the delivered Flask/MySQL course project.
Deferred features are scope decisions, not defects.

| Limitation | Current Impact | Current Mitigation | Possible Future Improvement | Reason It Is Outside Current Scope |
|---|---|---|---|---|
| No authentication or user accounts | Reports and claims are not associated with an authenticated identity. | The application is presented as a local course prototype and does not claim account-based privacy or ownership controls. | Add authentication, authorization, and user ownership rules after requirements and security review. | Authentication was not part of delivered US01–US07. |
| No administrative claim-review interface | Stored claims remain pending; the application cannot approve or reject them. | Claims are stored in MySQL with an initial `pending` status. | Implement the deferred US09 review workflow with authorization and audit rules. | US09 is deferred. |
| No claim-history page or claim-status tracking interface | A claimant cannot later browse claims or follow a status change in the UI. | The dedicated submission page confirms receipt and displays the initial Pending status. | Implement authenticated claim history and US08 status tracking. | US08 is deferred, and accounts are not implemented. |
| US08–US11 are deferred | Status tracking, claim review, item-status updates, and personal report lists are not delivered. | Current documentation separates delivered US01–US07 from deferred scope. | Reprioritise and re-estimate these stories in a future iteration. | The final baseline prioritises the implemented reporting, discovery, details, photo, and claim-submission workflow. |
| Automated database tests use fakes or mocks | The 21-test suite does not prove live MySQL connectivity or schema installation. | Parameterised SQL, commit behaviour, redirects, and cleanup are checked deterministically; repository screenshots record selected manual MySQL checks. | Add isolated integration tests against a disposable MySQL service. | A stable live-database automation environment was not part of this submission. |
| No automated browser testing | Cross-page browser interaction, responsive layout, and accessibility are not continuously verified. | Flask test-client coverage and repository-recorded manual screenshots cover representative paths. | Add browser end-to-end and accessibility tests. | Browser automation was not introduced in the delivered testing toolchain. |
| No recorded test-coverage percentage | The percentage of executable code exercised is unknown. | Test names and story mappings state exactly which behaviours are asserted. | Add a coverage tool and an agreed threshold after the baseline is stable. | No coverage tool or verified percentage exists in the repository. |
| No performance or load testing | Behaviour under concurrent or high-volume use is unknown. | The delivered use case is a small local prototype. | Define performance targets and run load tests with representative data. | Performance requirements were not defined for US01–US07. |
| No comprehensive security testing | CSRF, authorization, session hardening, abuse cases, and penetration risks have not been comprehensively assessed. | SQL uses parameters; displayed Jinja values are escaped by default; filenames use `secure_filename`; claim fields have server-side required validation. | Perform threat modelling, security testing, and production hardening before wider use. | The project is not presented as production-ready or publicly deployed. |
| Local deployment only | The Flask/MySQL application is not evidenced as publicly hosted. | Reproducible local setup and test commands are documented. A documentation page is not treated as application deployment. | Add a reviewed production deployment design, secret management, and WSGI hosting. | Public deployment was not part of the confirmed delivery evidence. |
| Upload validation is limited | Validation checks filename extension and sanitises the filename, but does not enforce MIME type, size, uniqueness, malware scanning, or orphan cleanup. | Only PNG, JPG, JPEG, and GIF extensions are accepted; new files under `static/uploads/` match the Git ignore rule. | Add content validation, size limits, collision-safe names, storage lifecycle controls, and security scanning. | Advanced upload hardening was not an acceptance requirement for US06. |
